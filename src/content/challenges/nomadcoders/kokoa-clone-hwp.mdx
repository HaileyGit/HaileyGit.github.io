"회사에서 몰래 쓸 수 있는 카톡" 컨셉으로, 한글(HWP) 워드 문서처럼 위장된 버전을 만들었다.
겉은 평범한 한글 문서지만 안에서는 7개 페이지를 오가며 채팅이 가능하다. 메뉴바·도구모음·줄자·열린 문서 탭·하단 상태바는 폰트어썸만으로 한글 UI 를 흉내냈고, 본문에는 채팅 transcript / 채팅 목록 / 연락처 / 검색 / 환경 설정 / 로그인 폼 같은 카톡 컨텐츠가 들어가 있다. 페이지 이동은 한글의 "열린 문서 탭" 으로 처리해서, 진짜 한글에서 문서 사이 오가듯 자연스럽게 화면이 바뀐다.

사실 이 기초반은 예전에 한 번 완주한 적이 있는 강의다.
그동안 일에서 AI 한테 코드를 시키는 데 너무 익숙해져서, 손으로 직접 타이핑하라고 하면 아예 못하게 되버리고, 원래 알던 개념들까지 다 잊어버리게 되는 바람에 코딩에 대한 재미와 자신감이 같이 떨어진 시기였다.
그래서 다시 처음부터, 같은 강의지만 이번엔 AI 의존을 최소화하면서 손코딩 baseline 복구 + 코딩 재미 되살리기, 이 두 가지가 이번 챌린지의 진짜 목표다.

튜터를 참고해서 나의 방향성에 맞춰 수정했다.
처음 원칙은 단순했다. "코드 짜줘" 금지, "방향만" OK. 구체적으로는

- 과제 받으면 try1 (뼈대) 을 손으로 작성
- 막히면 답 대신 검색 기준만 (예: "이 정렬에 쓰는 flex 속성 이름이 뭐예요?")
- try1 완성하면 "약점이 어디야" 진단 받아 feedback.md 에 정리
- 약점 고쳐서 try2 → try3, 그 다음 모범답안 대조
- 우아함 라운드 — 통과한 코드를 같은 기능 유지한 채로 스펙 트릭으로 더 짧고 깔끔하게 다시 짜기. 찾은 트릭은 feedback.md 에 누적

이렇게 하면 코드는 100% 손으로 치고, AI 는 "막힌 지점에서 검색 기준만 주는 친구" 역할이 된다.
졸업과제 (카톡 클론) 도 같은 패턴 — skeleton → feedback → 디테일 보정 → 우아함 라운드 → 사이드 트랙 (HWP 스킨) → 배포 흐름으로 진행했다.

1-2주를 거치며 깨달은 한 가지 — 손코딩이 효과적이었던 진짜 이유는 손 자체가 신성해서가 아니라 '몸이 막히기 때문' 이었다.
머리와 입은 자기기만이 쉽고 "이거 알아" 라고 통과시키기 쉽지만 손은 그게 안 된다. 외운 패턴은 손에서 더듬거리고, 그 더듬거림이 거짓말 탐지기 역할을 했던 것 같다.
이전에 챌린지를 했을 때보다 더 시간이 많이 걸렸다.

이 깨달음이 JS 부터는 튜터의 계획을 살짝 바꾼다.
손 baseline 은 어느 정도 돌아왔다고 보고, JS 부터는 두 가지로 무게중심을 옮기려고 한다.

**1) 라인별 "왜?" 인터뷰**

"동작한다" 를 통과 기준으로 두지 않으려고 한다. 코드 한 줄 한 줄에 "왜 이 API/구조를 골랐는가" 를 한 마디로 답할 수 있어야 통과. 답이 막히는 줄은 ⭐ 로 표시해서 feedback.md 에 모은다 — 그게 다음 drill 타깃이 되는 셈이다.

**2) 깨뜨려보기 실험**

"왜?" 답이 진짜인지 손으로 증명한다. 예를 들어 addEventListener 의 두 번째 인자가 함수 참조 라는 답을 했으면, handler() 로 한 글자만 바꿔서 진짜 즉시 실행되는지 콘솔에서 확인. 손 타이핑의 거짓말 탐지기 역할을, 한 줄짜리 실험으로 압축해서 가져가는 셈이다.

타이핑 자체는 강의/문서 코드를 가져와도 OK 다. 단, 한 과제당 핵심 한두 줄은 강의 끄고 콜드로 직접 — 손 baseline 이 무너지지 않게 하는 안전장치다 (분량 10-20% 정도).
